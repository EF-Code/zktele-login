Why this is anonymous & Sybil-resistant

  • Anonymity — the only value a dApp ever learns is a nullifier. The server response above contains no userId, name, or photo — they never leave the gateway.
  • Unlinkability — every login mints a fresh nullifier (a random salt is mixed in), so not even a server holding your full history can tell two logins belong to the same person.
  • Sybil-resistance — a proof can only be minted for a real, bot-signed Telegram session (the HMAC check happens inside the gateway), so identities can't be forged for free.
  • Freshness — the proof carries a timestamp; replayed, stale, or tampered proofs are rejected (try the replay button).
  • Domain binding — the app domain is hashed into the circuit, so a proof minted for this demo can't be replayed on another app.
