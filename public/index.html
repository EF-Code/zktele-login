Security boundary

  • Telegram authenticity — the gateway checks Telegram's HMAC and freshness before issuing anything.
  • Issuer authenticity — relying apps require an Ed25519 signature from the configured gateway; an arbitrary Groth16 proof is not accepted.
  • Scoped deduplication — the same Telegram account produces the same nullifier only for this app and action.
  • Privacy boundary — the gateway necessarily sees Telegram identity while validating it. Relying apps can operate on the signed nullifier instead.
  • Domain and policy binding — the gateway signature covers the domain, action, expiry policy, and full proof payload.
